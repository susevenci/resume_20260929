## 一、开篇：为什么这一讲能救你未来 90% 的慌

你有没有注意到一个现象：同样面对一个新事物，有人上手很快，有人处处卡壳。差距常常不在聪明程度，而在**脑子里有没有"挂钩"**——新知识能不能挂在已有的旧知识上。

这一讲的五个概念，是 Vibe Coding 世界里出现频率最高的五个词。它们每一个听起来都像"技术术语"，但我要告诉你一个秘密：**它们全部可以用你每天都有的生活经验来理解。**

文件、文件夹、网页三件套、部署、报错——学完之后你会发现，所谓的"技术门槛"，很多时候只是一层翻译纸：捅破了，里面全是你早就懂的东西。

而且这五个概念还有一个隐藏价值：**它们是你和 AI 精确对话的词汇基础。** 当你能说"帮我修改 index.html 里 JavaScript 部分的按钮逻辑"，而不是"那个文件里那个东西"，AI 的交付质量会上一个台阶。

## 二、概念一：文件——一切作品的最小单位

### 2.1 用你熟悉的经验理解

你每天和文件打交道：Word 文档、Excel 表格、手机里的照片、微信里的 PDF。文件就是**一个独立的、有名字、有格式的信息容器**。

代码世界一模一样。一个网页、一个工具，最终都是一个个文件。区别只在于格式不同——你看不见的 `.html`、`.css`、`.js` 文件，和你天天见的 `.docx`、`.jpg` 文件，地位完全平等。

### 2.2 你要认识的几种文件格式（就这几种，不多）

|     |     |     |     |
| --- | --- | --- | --- |
| 格式  | 是什么 | 类比  | 你需要做什么 |
| `.html` | 网页文件 | 一张海报 | 双击就能在浏览器打开，这是你的主战场 |
| `.md` | Markdown 文本 | 一份纯文字笔记 | 用记事本就能看，你正在读的教程就是 |
| `.css` | 样式文件 | 海报的配色方案 | 不用碰，AI 会管 |
| `.js` | 脚本文件 | 海报上的机关装置 | 不用碰，AI 会管 |
| `.jpg/.png` | 图片  | 照片  | 放进文件夹备用 |
| `.json` | 数据文件 | 一张表格 | 知道它存数据就行 |

**记忆技巧：你只需要真正认识** `**.html**` **和** `**.md**`**。** 其他格式，知道"它们存在、AI 会处理"就够了。就像你不需要懂印刷机，也能出书。

### 2.3 文件命名的三条铁律（违反必出事）

1.  **必须有后缀名。** `index` 不是文件，`index.html` 才是。Windows 电脑尤其注意：系统默认隐藏后缀，你可能以为自己建的是 `index.html`，实际建成的是 `index.html.txt`——双击打不开时，先查这个（右键→属性看真实后缀）。

1.  **名字里不要有空格和特殊符号。** `我的简历 最终版!!!.html` 这种名字，AI 和服务器都可能读懵。用连字符：`我的简历-v2.html`。

1.  **见名知意。** `a.html`、`新建文本文档(2).html` 这种名字，三天后你自己都不知道是什么。用 `首页.html`、`打卡工具-0803.html`。

## 三、概念二：文件夹——作品的"抽屉"

### 3.1 用你熟悉的经验理解

你电脑里一定有"工作""生活""照片"这样的文件夹。文件夹就是**把相关文件装在一起的容器**——一个抽屉、一个收纳盒。

做 Vibe Coding 作品，逻辑完全一样：**一个作品 = 一个专属文件夹**，这个作品的所有文件（页面、图片、素材）都住在里面。

### 3.2 为什么这件事值得专门讲

因为小白丢作品、搞混文件、AI"找不到你说的文件"，90% 是文件夹混乱导致的。典型灾难现场：

-   所有作品堆在桌面，三十个 `index.html` 分不清谁是谁；

-   图片一半在"下载"一半在"图片"，网页显示不出来；

-   让 AI"修改首页"，结果它改了另一个文件夹里的同名文件。
    

**文件夹结构，就是你给 AI 准备的工作环境。** 你给实习生的办公桌有多整齐，实习生的活就干得有多漂亮——AI 一模一样。

### 3.3 标准结构（照抄即可，第 9 讲会带你实操）

```Plain
作品名/
├── 01-当前版/      ← 正在做的最新版本
├── 02-历史版本/    ← 每个阶段的存档（后悔药）
└── 03-素材/        ← 图片、需求草稿、参考文档
```

现在只需要记住这张图。三个文件夹，各司其职，一辈子够用。

## 四、概念三：网页三件套——骨架、皮肤、动作

### 4.1 用装修房子来理解

这是五个概念里最重要的一个，值得多花点篇幅。

一个网页，由三种文件配合完成。把它们想象成装修一套房子：

**HTML = 房子的格局（骨架）**

几室几厅、哪里是门哪里是窗——HTML 决定页面上**有什么**：标题、段落、按钮、图片、输入框。它只关心"存在"，不关心"美丑"。

**CSS = 装修和软装（皮肤）**

墙刷什么颜色、地板什么材质、窗帘什么风格——CSS 决定页面**长什么样**：颜色、字体、大小、间距、圆角、阴影。

**JavaScript = 水电和智能家居（动作）**

灯的开关、空调遥控器、扫地机器人——JavaScript 决定页面**能干什么**：点击有反应、数字会变化、数据能存取。

### 4.2 一个具体例子

假设页面上有一个蓝色按钮，点击会弹出"报名成功"：

-   **HTML** 负责：页面上存在一个按钮，上面写着"马上报名"；

-   **CSS** 负责：这个按钮是蓝色的、圆角的、字是白色的、大小合适；

-   **JavaScript** 负责：你点击它的时候，真的弹出一个写着"报名成功"的框。
    

三者缺一，按钮要么是幽灵（不存在）、要么是毛坯（丑）、要么是模型（点了没反应）。

### 4.3 为什么你需要懂这个（你不是不用写代码吗？）

**因为你需要"验收"和"提修改意见"。**

当 AI 交付一个页面，你说"不好看"——AI 怎么知道改哪里？但如果你能说出：**"格局不用动（HTML），把装修改一下（CSS）：按钮换成圆角、颜色换成藏蓝"**——AI 一次就能改对。

这就是懂三件套的实际收益：**你的反馈精度，从"感觉不对"升级到"哪一层不对"。**

|     |     |     |
| --- | --- | --- |
| 你想改什么 | 该说哪一层 | 示例话术 |
| 加个板块、删个按钮、改文案 | HTML（骨架） | "在页面底部加一个'常见问题'板块" |
| 换颜色、调字号、改间距 | CSS（皮肤） | "把标题字号调大，颜色换成藏蓝" |
| 点击没反应、数据不对、加个功能 | JavaScript（动作） | "点提交按钮没反应，帮我检查并修复" |

## 五、概念四：部署——把作品"贴到大街上"

### 5.1 用你熟悉的经验理解

你在家写了一幅字，只有来你家的客人能看到。想让大家都能看到？得把它印成海报，贴到大街的公告栏上。

**部署，就是"贴海报"的过程**：把存在你电脑里的文件，上传到一台 24 小时开机、连接互联网的电脑（叫"服务器"）上。上传之后，你会得到一个网址，世界上任何人点开这个网址，就能看到你的作品。

### 5.2 关于部署，你现在只需要记住三句话

1.  **不部署，作品只有你一个人能看；部署了，全世界都能看。**

1.  **部署可以是完全免费的**，而且有手把手的办法（第 26 讲会带你做，5 分钟）。

1.  **部署后改内容 = 重新贴海报**：把新文件重新传上去，覆盖旧的，网址不变，内容更新。
    

### 5.3 一个常见误会

"部署是不是要买服务器、懂运维？"——这是 2010 年的老黄历了。现在有一批平台（GitHub Pages、Vercel 等）专门帮你托管静态网页，免费、稳定、还给你分配网址。你要做的只是"上传文件"，像在网盘里传照片一样。第 26 讲见。

## 六、概念五：报错——AI 给你的"求助信号"

### 6.1 先治心病：报错不是事故，是沟通

小白看到满屏红色英文的本能反应是："完了，我搞坏了。"

请把这句话刻进脑子里：**报错不是"你搞坏了"，而是程序在用（蹩脚的）语言告诉你"我哪里不舒服"。** 它是求救信号，不是死亡通知书。

类比：你家的智能音箱突然说"我没连上网络"——你不会觉得它坏了，你知道它在报告状况。报错完全是一回事，只是语气没那么友好。

### 6.2 看懂报错的"三段式"（不用懂英文，看结构）

一条典型报错长这样：

```Plain
Uncaught ReferenceError: myFunction is not defined
    at index.html:42
```

看不懂？没关系，只看三个位置：

1.  **错误类型**（ReferenceError）——相当于"病症名"。你不需要知道什么意思，复制给 AI 就行；

1.  **错误描述**（myFunction is not defined）——"哪里不舒服"。同样，复制给 AI；

1.  **位置**（index.html:42）——**这是最有价值的部分**：它告诉你问题出在哪个文件的第 42 行。就像疼痛定位："医生，是这里疼。"
    

### 6.3 你唯一需要掌握的动作

遇到报错，做三件事：

1.  **复制报错原文**（别截图一半、别自己改写，原封不动）；

1.  **发给 AI，附上一句**："我双击打开 index.html 后出现这个报错，帮我看看是什么原因、怎么修："；

1.  **等 AI 给修复方案**，照着做或者让它直接改。
    

90% 的报错，这一轮就能解决。剩下 10%，第 23 讲（调试的艺术）和第 28 讲（报错自救手册）专门伺候。

## 七、动手做（本讲作业）

**任务一：建出你的第一个标准作品文件夹（5 分钟）**

1.  在你常用的位置（桌面或文档）新建文件夹，命名：`简历页作品`；

1.  在里面建三个子文件夹：`01-当前版`、`02-历史版本`、`03-素材`；

1.  进入 `01-当前版`，新建一个文件 `hello.html`，用记事本或 VS Code 打开，写一行字：`你好，这是我的第一个文件`，保存；

1.  双击 `hello.html`——浏览器打开，显示你的字。
    

**任务二：故意制造一次报错（5 分钟，脱敏治疗）**

1.  把 `hello.html` 里的内容删掉一半（比如只留"你好"两个字后面加一半乱码符号），保存；

1.  双击打开，观察浏览器的样子（大概率空白或异常）；

1.  深呼吸，告诉自己：没坏，这只是报错。然后把内容改回去。
    

这一步的意义：让你在最安全的环境里经历一次"出错"，打一针心理疫苗。

**自检清单：**

-   \[ \] 我能说出 HTML、CSS、JavaScript 分别管什么？

-   \[ \] 我知道改"颜色字号"该提 CSS，改"加个板块"该提 HTML？

-   \[ \] 我知道报错里的"index.html:42"是什么意思？

-   \[ \] 我的标准文件夹建好了？
