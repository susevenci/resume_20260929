## 一、开篇：从"文件"到"网址"的成人礼

你的作品做到今天，有一个巨大的遗憾：**它们还困在你的电脑里。**

想给朋友看你的个人网站，只能发文件，对方还得知道"双击打开"；想在手机上随时打开，得先传到自己微信；想让更多人看到——没门。

这一讲要完成的，是你作品的"成人礼"：\*\*部署（上线）——把文件上传到 24 小时开机的服务器，获得一个公开网址。\*\*从此以后：

-   你的网址是 `你的名字.github.io`，谁点开都能看；

-   手机、电脑、平板，随时随地访问；

-   发给别人，点开就看，不需要任何说明。
    

而且今天学的三种方式，**全部免费、全部不需要买服务器、全部在 10 分钟内完成。**

---

## 二、先建立心智：部署到底是怎么回事（3 分钟）

把第 3 讲的概念拿出来复习：部署 = 把文件"贴到大街的公告栏"。

```Plain
你的电脑（只有你能看）
    ↓ 上传
服务器（24 小时开机，连着互联网）
    ↓ 分配
网址（任何人输入都能访问）
```

三种方式的区别只在"公告栏"是哪家。我按推荐顺序讲：\*\*GitHub Pages（最经典）、Vercel/Netlify（最快捷）、国内平台（国内访问最快）。\*\*学完任选其一即可，不必全会。

---

## 三、方式一：GitHub Pages（推荐，免费且稳定）

GitHub 是全球最大的代码托管网站（程序员的"百度网盘"），它的 Pages 功能可以免费托管静态网页，还送你一个 `你的名字.github.io` 的网址。

### 3.1 注册（3 分钟）

1.  打开 github.com，点 Sign up；

1.  填邮箱、设密码、起用户名——**用户名会出现在你的网址里**（`用户名.github.io`），起个像样的；

1.  验证邮箱，完成。
    

### 3.2 建仓库（2 分钟）

1.  登录后，右上角 "+" → "New repository"；

1.  Repository name 填：`my-site`（或你喜欢的英文名，**小写、连字符、无空格**）；

1.  选 **Public**（必须公开才能免费用 Pages）；

1.  点 "Create repository"。
    

### 3.3 上传文件（2 分钟）

1.  在新仓库页面，点 "uploading an existing file" 链接；

1.  把你 `01-当前版` 里的**所有文件和文件夹**拖进页面（首页 `index.html` 必须在最外层）；

1.  拉到页面底部，点绿色按钮 "Commit changes"。
    

### 3.4 开启 Pages（2 分钟）

1.  仓库顶部点 "Settings"（齿轮）→ 左侧栏点 "Pages"；

1.  Source 选 "Deploy from a branch"，Branch 选 "main"，点 Save；

1.  等 1-2 分钟，刷新页面——顶部会出现你的网址：`https://你的用户名.github.io/my-site/`。
    

**点开它。你的作品，上线了。**

### 3.5 以后怎么更新

改完本地文件后：回仓库 → 找到对应文件 → 点进去 → 右上角铅笔旁的 "..." → "Delete file" 删掉旧的 → 重新上传新文件（或者直接在文件列表页 "Add file → Upload files" 上传同名文件覆盖）。网址不变，内容更新。

## 四、方式二：Vercel / Netlify（最快捷，3 分钟）

这两个是专门做网站托管的平台，流程比 GitHub 更傻瓜：

1.  打开 vercel.com（或 netlify.com），用邮箱注册；

1.  点 "Add New / Deploy"，选择上传你的**整个作品文件夹**（Netlify 直接把文件夹拖进页面指定区域即可）；

1.  等 3-10 秒，它自动给你一个网址（`xxx.vercel.app`）。
    

**优势：** 快到离谱，拖个文件夹就完事；更新也是重新拖一次。

**适合：** 着急分享、不想碰 GitHub 的人。

**注意：** 免费版对个人项目完全够用；网址是平台后缀，不如自己域名正式（第 27 讲解决）。

---

## 五、方式三：国内平台（国内访问最快）

GitHub 和 Vercel 的服务器在海外，国内访问偶尔慢。如果你的读者主要在国内：

-   **Gitee Pages**：gitee.com（国内版 GitHub），流程和 GitHub Pages 几乎一样；

-   **各类静态托管**（又拍云、七牛等）也需实名认证。
    

**注意：** 国内平台大多需要**实名认证**（上传身份证），介意的话用方式一/二即可——海外平台慢一点，但绝大多数情况下完全能正常访问。

## 六、上线前必查清单（防止上线即翻车）

部署前花 2 分钟过一遍，避免"上线就打不开"：

-   \[ \] **首页文件名是** `**index.html**`（服务器认这个门牌）；

-   \[ \] 所有链接是相对路径（没有 `file:///Users/...` 这种你电脑的路径）——让 AI 扫一遍："检查所有链接是否为相对路径"；

-   \[ \] 图片、素材文件**一起上传了**（光传 HTML，图片全裂）；

-   \[ \] 文件名没有空格和特殊符号（中文名部分平台不支持，建议英文化）；

-   \[ \] 上线后用\*\*手机 4G（断开 WiFi）\*\*打开测一遍——确认是真正的公网可访问。

## 八、常见坑（FAQ)

**Q1："部署后网址打不开，显示 404？"**

90% 是首页文件名不对（必须是 `index.html`，不是 `首页.html` 或 `index.HTML`），或文件没有放在仓库最外层。检查这两处。

**Q2："图片全部裂开？"**

两个原因：① 图片文件没上传（只传了 HTML）；② 引用路径错了（HTML 里写的是 `03-素材/图.jpg`，但你上传时文件夹结构变了）。让 AI 对照你的实际上传结构修路径。

**Q3："GitHub 访问很慢/打不开？"**

国内网络访问 GitHub 偶尔不稳定。对策：多刷新、换网络、或用方式二/三。这不影响你部署好的网站被别人访问（多数地区正常）。

**Q4："我的作品里有 localStorage 数据，部署后还有吗？"**

有，但要注意：localStorage 存的是**每个访客自己浏览器里**的数据。你的看板部署后，你在你浏览器里记的数据只有你能看到——别人访问是空白的。这正是"个人工具"部署后的正常形态：每个人拥有自己的一份数据。

**Q5："免费版会被关停或加广告吗？"**

GitHub Pages 和 Vercel 的免费额度对个人静态网站基本无限制、无广告，可放心长期使用。
